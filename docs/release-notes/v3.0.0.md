## 修复

TODO：以下 5 条来自未发布的 `v2.3.9`（相关代码已在仓库中，随 `v3.0.0` 一并发出），**本次大版本自身的修复项待补充**。格式沿用历史版本：**一句话结论** + 现象 + 现在的行为 + 影响范围（哪些场景不受影响）。

- **修复企业微信应用 mpnews 图文消息正文不换行**：mpnews 的正文（content）按 HTML 渲染，此前正文里的换行不生效。现在正文中的换行会正确转换为 `<br>` 显示；描述（digest）等纯文本字段以及 text、markdown 等其它消息类型的换行行为保持不变，不受影响。
- **修复 Edge/Chromium 下点击最小化被强制拉回全屏**：窗口最小化时浏览器会上报窗口宽度为 0，此前被误判为移动端，导致弹窗全屏、侧栏收起、页面切到移动端布局（切到别的标签页再切回来才恢复）。现在对“宽度为 0/页面隐藏”的异常尺寸加了守卫，最小化不再翻转布局；真实移动端与正常窗口缩放不受影响。
- **修复桌面版 Python 版本缺失直接启动失败**：当任务配置的 Python 版本（如 3.12）本机未安装、但装了其它受支持版本（如 3.11）时，面板会自动回退到已安装的版本运行，并在日志中提示“已回退到 x.x”，不再直接报“Python x.x 不可用”而中断。Windows 上仅通过 `py` 启动器安装的 Python 也能被正确识别。任务表单会标注未安装的版本，新任务默认选中已安装的版本。桌面/二进制版与面具（Magisk）版回退行为一致；已安装所请求版本时仍然尊重该版本、不会回退。
- **修复随机延迟误延迟手动执行的任务**：设置“随机延迟最大秒数”后，此前手动点击执行的任务也会被排队延迟。现在随机延迟只跳过手动执行——手动点击立即运行；定时（cron）与开机运行仍按配置错峰，开机任务的错峰能力不再丢失。想让某个任务开机不等待，把它的“随机延迟秒数”显式设为 0 即可。
- **修复「定时任务最大并发数」与「不允许多实例」从未真正生效**：此前调度器只在“派发”阶段计数，任务一启动就释放了槽位，导致并发数填 1 还是 128 都不限制同时运行的任务数，「不允许多实例」也拦不住执行期间的重复触发。现在槽位会一直持有到任务真正结束（含全部重试），并发数成为真实上限，同一任务在执行期间的重复触发会被拒绝。随机延迟改为在占用槽位之前等待，不会再空占并发名额；调度阶段出现异常时名额会被正常归还，不会一次异常就永久少掉一个并发名额。
- **修复开机任务一拥而上**：并发闸门生效后，把「定时任务最大并发数」设为 1，开机运行的任务就会按任务排序（`sort_order`）逐个执行，前置任务排在第一位即可，不必再把前置脚本复制进每个任务。

  > **注意随机延迟与排序的相互作用**：随机延迟是通过“等待到期后重新排队”实现的，所以**带非零随机延迟的开机任务，实际先后由延迟到期时间决定，不再遵循 `sort_order`**（并发数为 1 时仍然保证一次只跑一个，只是顺序是乱的）。两种编排方式二选一即可：
  >
  > - **靠排序**：把开机任务的「随机延迟秒数」全部显式设为 0，顺序完全由 `sort_order` 决定；
  > - **靠延迟**（v2.3.8 及更早的老办法）：前置任务设 0、其余保留延迟，前置任务因为不等待而必然先入队先执行。
- **修复关机时被运行中的任务拖住**：关闭或重启面板时，现在先停止接收新任务并中断执行中的子进程，再回收调度线程，不用等满超时。
- **修复多设备登录后旧会话无限加载**：当同时在线设备超过“同时在线人数”限制、较早的登录被顶下线后，旧设备/页面此前会卡在无限加载，必须退出重新登录。现在旧会话的请求会正确失效并跳转到登录页，不再卡死。

- **「定时任务最大并发数」首次真正生效（默认 5）**：升级前这个开关形同虚设，所有任务实际不受限并发；升级后同时运行的任务最多 5 个，其余排队等待。任务多的用户会直观感到“变慢了”，这是修复不是退化。需要更高并发请到 设置 → 调大「定时任务最大并发数」。
- **卡死的任务会占用并发名额**：升级前一个 hang 住的任务不影响别的任务；升级后它会一直占着一个名额，若把名额占满调度会停摆。请给可能卡死的任务设置「超时时间」（默认 0 表示不限制）。
